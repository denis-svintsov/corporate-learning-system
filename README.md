# Система корпоративного обучения

ВКР-проект: микросервисная платформа для организации корпоративного обучения сотрудников. Система позволяет выбирать и назначать курсы, вести обучение, отмечать посещаемость, общаться в чатах курсов, получать уведомления, формировать аналитику и выдавать PDF-сертификаты.

## Основные возможности

- Авторизация и регистрация сотрудников с ролевой моделью.
- Каталог назначенных курсов и самостоятельный выбор курсов сотрудником.
- Модерация заявок на обучение и настройка лимитов выбора.
- Создание и редактирование курсов технологом или администратором.
- Загрузка обложек курсов в MinIO.
- Ведение курсов экспертом: участники, посещаемость, чат курса, подтверждение завершения.
- Автоматическая генерация PDF-сертификата после завершения курса.
- Хранение сертификатов и обложек в MinIO.
- Уведомления о событиях обучения.
- Аналитика по прогрессу, курсам, вовлеченности и уведомлениям.
- Чат-бот на странице чатов для навигации по платформе.

## Ролевая модель

| Роль | Назначение |
| --- | --- |
| `USER` | Сотрудник: проходит назначенные курсы, выбирает доступные курсы, скачивает сертификаты. |
| `MANAGER` | Руководитель подразделения: просматривает аналитику по обучению. |
| `HR` | HR-менеджер: согласует заявки, назначает обучение, просматривает аналитику, ведет курсы. |
| `TECHNOLOG` | Технолог: создает и редактирует курсы, настраивает доступ и параметры обучения. |
| `EXPERT` | Эксперт: ведет курсы, отмечает посещаемость, общается с участниками, подтверждает завершение. |
| `ADMIN` | Администратор: полный доступ к управлению, заявкам, курсам и аналитике. |

## Архитектура

Проект построен как набор сервисов, объединенных через API Gateway.

| Сервис | Назначение |
| --- | --- |
| `frontend` | React/Vite интерфейс платформы, доступен на `http://localhost:5000`. |
| `gateway` | Spring Cloud Gateway, единая точка входа API на `http://localhost:8080`. |
| `auth` | Авторизация, JWT, сессии, демо-пользователи. |
| `users` | Профили сотрудников, подразделения, должности, настройки личного кабинета. |
| `courses` | Курсы, назначения, заявки, прогресс, посещаемость, сертификаты, MinIO. |
| `communication` | Чаты, комнаты курсов, сообщения. |
| `notifications` | Уведомления и статистика доставки. |
| `analytics` | Дашборд аналитики, отчеты, агрегированные показатели. |
| `postgres` | Базы данных сервисов. |
| `kafka` | События завершения курсов и уведомления. |
| `redis` | Rate limiting gateway и служебное кэширование. |
| `minio` | Файловое хранилище сертификатов и обложек курсов. |

## Технологии

- Frontend: React, TypeScript, Vite, Tailwind CSS, TanStack Query, Wouter.
- Backend: Java 21, Spring Boot, Spring Security, Spring Cloud Gateway, Spring Data JPA.
- Инфраструктура: Docker Compose, PostgreSQL, Flyway, Kafka, Redis, MinIO.
- Документы: генерация PDF-сертификатов через OpenPDF.

## Быстрый запуск

Требования:

- Docker и Docker Compose.
- Свободные порты: `5000`, `8080`, `5432`, `6379`, `9000`, `9001`, `9092`, `9093`.

Запуск:

```bash
docker compose up --build
```

После запуска:

- Frontend: `http://localhost:5000`
- API Gateway: `http://localhost:8080`
- MinIO Console: `http://localhost:9001`
- MinIO логин/пароль: `minioadmin` / `minioadmin`

Если база уже поднималась со старыми миграциями и Flyway сообщает о checksum mismatch, очистите volume и запустите заново:

```bash
docker compose down -v --remove-orphans
docker compose up --build
```

Точечная очистка только данных PostgreSQL:

```bash
docker compose down
docker volume rm sdo_postgres_data
docker compose up --build
```

## Сценарий демонстрации

1. Войти под `denis / 12345678`.
2. Открыть `/catalog` и посмотреть назначенные курсы.
3. Открыть `/selection`, выбрать доступный курс и отправить заявку.
4. Войти под `hr / 12345678` или `ivan / 12345678`.
5. На `/admin` согласовать заявку.
6. Войти под `technolog / 12345678`.
7. На `/admin/courses` создать или отредактировать курс, загрузить обложку.
8. Войти под `expert / 12345678`.
9. На `/teaching` отметить посещаемость и нажать `Подтвердить завершение`.
10. Вернуться под сотрудником и открыть `/certificates`.
11. Скачать PDF-сертификат.
12. Проверить уведомления в шапке и на `/notifications`.
13. Открыть `/analytics` под администратором, HR, руководителем или технологом.

## Сертификаты и MinIO

Сертификат генерируется автоматически после подтверждения завершения курса на странице `/teaching`.

Файлы сертификатов не хранятся в базе данных. В БД сохраняются метаданные сертификата и ключ объекта, а PDF хранится в MinIO bucket `sdo-certificates`.

Обложки курсов загружаются на странице `/admin/courses` и хранятся в bucket `sdo-course-covers`.

## API через Gateway

Основной адрес API: `http://localhost:8080`.

Маршруты gateway:

- `/auth/**` -> auth service
- `/users/**`, `/departments/**`, `/positions/**` -> users service
- `/courses/**`, `/progress/**`, `/lessons/**`, `/certificates/**` -> courses service
- `/chat/**`, `/ws/chat/**` -> communication service
- `/notifications/**` -> notifications service
- `/analytics/**` -> analytics service

Для защищенных запросов используется JWT в заголовке:

```http
Authorization: Bearer <token>
```

## Примечания для разработки

- Миграции Flyway лежат в `src/main/resources/db/migration` каждого backend-сервиса.
- При изменении уже примененных миграций на существующей базе потребуется очистка volume или `flyway repair`.
- Frontend обращается к API через gateway на `http://localhost:8080`.
- В Docker Compose имена сервисов используются как DNS-имена внутри сети: `auth`, `users`, `courses`, `analytics`, `notifications`, `communication`.
- Исторические файлы документов ВКР в корне репозитория не требуются для запуска приложения.
